BagyoAlert PH — typhoon alert & relief platform

Serverless + event-driven + multi-Region DR

Real-world problem

Every typhoon season, a local government's website crashes exactly when residents need it most. Traffic jumps 50× for a few days, then drops to almost nothing. Relief requests get lost, alerts only go out in English, and there's no backup if the data center floods.

Walk the request: all 17 steps in one list
  1. Resident opens the site. Route 53 resolves the domain; failover routing can point to a second Region if a health check fails.
  2. CloudFront serves pages from the nearest edge location, so the surge never reaches the origin.
  3. WAF blocks bots and SQL injection; Shield Standard absorbs DDoS automatically, free.
  4. On a cache miss, CloudFront fetches the static site and advisories from S3.
  5. API calls (submit request, ask a question) go to API Gateway, which throttles abusive traffic.
  6. Responders sign in with Cognito; API Gateway checks their token.
  7. Lambda runs only when a request arrives, scaling from zero to thousands in parallel.
  8. Requests are dropped into SQS, so none are lost while the backend catches up; repeated failures go to a dead-letter queue.
  9. Worker Lambdas pull from the queue. They're idempotent, so a duplicate message never creates a duplicate relief ticket.
  10. DynamoDB (on-demand) stores relief requests and evacuation-center capacity.
  11. Global Tables replicate the data to a second Region for disaster recovery.
  12. Damage photos upload straight to S3 with a presigned URL.
  13. Rekognition labels each photo (flooded road, damaged house) so responders can prioritize.
  14. Chat questions go to Bedrock with the LGU's advisories as a knowledge base. The app, not the model, reads the database.
  15. Translate turns replies into Filipino or Cebuano; Polly reads alerts aloud for radio and hotlines.
  16. EventBridge fires when a new weather bulletin is published.
  17. SNS sends one alert to every subscriber at once by SMS, push and email.

4-domain map

D1Cloud Concepts · 24%

Elasticity (scale to zero and back), pay-as-you-go instead of servers sitting idle between storms, high availability (managed services span AZs) plus multi-Region DR, edge locations. Well-Architected: Reliability and Cost Optimization.

D2Security & Compliance · 30%

WAF, Shield Standard, Cognito, least-privilege IAM roles for each Lambda, encryption at rest by default (S3, DynamoDB), CloudTrail, Config. Shared responsibility: with serverless, AWS patches the OS and runtime; the LGU owns data, IAM and WAF rules.

D3Technology & Services · 34%

Route 53, CloudFront, S3, API Gateway, Lambda, SQS, DynamoDB, EventBridge, SNS, CloudWatch, X-Ray. AI/ML: Bedrock, Rekognition, Translate, Polly.

D4Billing, Pricing & Support · 12%

Lambda and DynamoDB on-demand bill per request, so quiet months cost almost nothing. Budgets alerts, Cost Explorer, cost allocation tags. Shield Advanced is a paid upgrade (DDoS response team + cost protection).

KlinikaCloud — patient records & telehealth for a clinic chain

Containers in private subnets + Multi-AZ database + security tooling

Real-world problem

A chain of clinics keeps patient records on one server in a back office. If it fails, doctors can't see charts. Lab results arrive as scanned paper, nobody knows who accessed what, and auditors keep asking for proof of security controls.

Walk the request: all 13 steps in one list
  1. Patient or doctor opens the portal; Route 53 resolves it.
  2. CloudFront + WAF filter traffic; an ACM certificate gives HTTPS.
  3. Requests go to the ALB in the public subnets.
  4. The ALB sends users to Cognito to sign in (MFA required for doctors).
  5. Layer-7 path routing sends /records and /appointments to ECS services on Fargate in private subnets across 2 AZs. Security group: only the ALB may connect.
  6. The app talks to RDS over TLS. Security group: only the app tier may connect. Storage encrypted with KMS.
  7. RDS replicates synchronously to a standby in a second AZ and fails over automatically.
  8. The app calls a third-party payment API out through the NAT Gateway. Outbound only; the internet can't reach in.
  9. Scans and lab results are stored in S3 (SSE-KMS, Block Public Access, presigned URLs) through a VPC endpoint.
  10. Textract pulls text and tables out of scanned lab forms.
  11. Comprehend Medical picks out medications, conditions and protected health info.
  12. Bedrock drafts a visit summary that the doctor reviews and approves.
  13. At startup the ECS task role fetches the database password from Secrets Manager. Nothing is hard-coded.

4-domain map

D1Cloud Concepts · 24%

High availability (Multi-AZ RDS, Fargate in 2 AZs). Migration: Replatform the clinic server to RDS (7 Rs). Shared responsibility: AWS runs Fargate hosts and patches the RDS engine; the clinic owns data, IAM, security groups and encryption settings. Well-Architected: Security and Reliability.

D2Security & Compliance · 30%

Cognito MFA, IAM task roles, security groups, private subnets, NAT outbound-only, KMS, Secrets Manager, ACM, WAF, GuardDuty, Inspector, Macie, Security Hub, CloudTrail, Config rules, AWS Artifact for auditors.

D3Technology & Services · 34%

Route 53, CloudFront, ALB, VPC, ECS, Fargate, ECR, RDS, S3, AWS Backup. AI/ML: Textract, Comprehend Medical, Bedrock.

D4Billing, Pricing & Support · 12%

Compute Savings Plans for steady Fargate; RDS Reserved Instances for a 24/7 database; Budgets and Cost Explorer (NAT Gateway and ALB bill by the hour); Business Support for 24/7 production help; Trusted Advisor.

PadalaTrack — delivery fleet tracking, analytics & migration

Streaming + data lake + ML + hybrid migration

Real-world problem

A courier company can't tell customers where their parcel is, plans routes by hand every night, and runs its warehouse on an aging on-prem Oracle database. Management wants dashboards and delivery-time predictions without buying more servers.

Walk the request: all 19 steps in one list
  1. GPS devices on each truck publish location every few seconds over MQTT to IoT Core, each authenticated by its own X.509 certificate.
  2. An IoT rule streams the messages into Kinesis Data Streams.
  3. Lambda processes the stream in near real time.
  4. The latest position per truck is written to DynamoDB.
  5. Customers' "track my parcel" screen reads that position.
  6. Positions are checked against geofences in Amazon Location Service.
  7. "Truck entered customer's barangay" becomes an event on EventBridge.
  8. An EventBridge rule routes it to SNS.
  9. The customer gets an SMS: "Your parcel is 10 minutes away."
  10. The same stream is also delivered by Data Firehose.
  11. ...into the S3 data lake, with lifecycle rules moving old data to Glacier.
  12. A Glue crawler builds the data catalog.
  13. Athena runs SQL directly on S3, billed per data scanned.
  14. QuickSight turns the queries into dashboards for operations managers.
  15. SageMaker trains a delivery-time (ETA) model on the company's own history.
  16. Step Functions orchestrates nightly route optimization on EC2 Spot instances in an Auto Scaling group.
  17. The warehouse connects securely through Site-to-Site VPN (or Direct Connect for dedicated bandwidth).
  18. DMS copies the data while SCT converts the Oracle schema to PostgreSQL.
  19. Orders and inventory now live in Aurora PostgreSQL. That's Replatform.

4-domain map

D1Cloud Concepts · 24%

Migration (7 Rs): Replatform Oracle → Aurora, Retire the old reporting server. Hybrid deployment model. Elasticity (Spot fleet only at night), trading CapEx for OpEx, economies of scale. Well-Architected: Performance Efficiency and Cost Optimization.

D2Security & Compliance · 30%

IoT device certificates, IAM roles with least privilege, Organizations SCPs + Control Tower guardrails across accounts, encrypted VPN tunnel, KMS on the data lake.

D3Technology & Services · 34%

IoT Core, Kinesis, Firehose, Lambda, DynamoDB, Amazon Location, EventBridge, SNS, S3, Glue, Athena, Step Functions, EC2 + Auto Scaling, VPN/Direct Connect, DMS, SCT, Aurora, CloudWatch. Analytics: Glue, Athena, QuickSight. AI/ML: SageMaker.

D4Billing, Pricing & Support · 12%

Spot for interruptible batch (up to 90% off), Reserved Instances for always-on Aurora, consolidated billing volume discounts, cost allocation tags per branch, Compute Optimizer rightsizing, Athena pay-per-query, S3 lifecycle to Glacier.

BahayHub PH — real-estate listings, leads & title documents

Managed platform (PaaS) + search + contact center + offline data migration

Real-world problem

Brokers post the same property on five different sites, buyers can't search by budget and location in one place, phone leads go unrecorded, and 40 TB of scanned land titles sit on one office file server with slow internet and no backup.

Walk the request: all 16 steps in one list
  1. A buyer opens the site; Route 53 resolves the domain.
  2. Amplify Hosting serves the React site on a global CDN and redeploys on every Git push.
  3. Buyers sign in with Cognito (Google or Facebook login) to save searches.
  4. The site calls the listings API on Elastic Beanstalk, which created the EC2 instances (with EBS volumes), the ALB and the Auto Scaling group for us.
  5. OpenSearch handles searches like "3BR near MRT under ₱8M" with full-text and map filters.
  6. Personalize ranks "homes you may like" from browsing history (useful for real builds, not on the exam list).
  7. Listings, leads and viewing schedules live in Aurora Serverless v2, which scales capacity with demand.
  8. A zero-ETL integration copies data into Redshift for price-trend analytics.
  9. When a broker publishes a listing, the app sends a NewListing event to EventBridge.
  10. EventBridge triggers SES to email buyers whose saved searches match.
  11. Callers reach the broker hotline on Amazon Connect.
  12. A Lex bot answers FAQs and books viewings through the listings API.
  13. Calls are recorded and Transcribe turns them into text for lead notes and coaching.
  14. The 40 TB of scanned titles would take weeks over the office internet, so they're copied onto a Snowball Edge device.
  15. AWS loads the device into S3; lifecycle rules move old titles to Glacier Deep Archive.
  16. Kendra lets staff ask "Which titles list a mortgage annotation?" and finds the answer inside the documents.

4-domain map

D1Cloud Concepts · 24%

Stop guessing capacity (Auto Scaling, Aurora Serverless). CAF People and Business perspectives (train brokers, measure lead conversion). Data migration with the Snow Family. Well-Architected: Operational Excellence (CloudFormation, managed platform updates) and Sustainability (capacity follows demand).

D2Security & Compliance · 30%

Cognito social login, IAM Identity Center for staff SSO, WAF + Shield, KMS encryption on S3/Aurora and on the Snowball device, Detective. Shared responsibility: even under Beanstalk, the guest OS on EC2 is the customer's job, so patch it (Systems Manager or managed platform updates).

D3Technology & Services · 34%

Route 53, Amplify, Elastic Beanstalk (EC2, EBS, ALB, Auto Scaling), OpenSearch, Aurora, Redshift, EventBridge, SES, Amazon Connect, Snowball Edge, S3 + Glacier Deep Archive, CloudFormation, Systems Manager, WorkSpaces. AI/ML: Lex, Transcribe, Kendra (Personalize beyond exam).

D4Billing, Pricing & Support · 12%

Elastic Beanstalk has no extra charge (you pay for the EC2, ALB and so on it creates). Reserved Instances for the steady baseline, Aurora Serverless billed for capacity used, Pricing Calculator, AWS Marketplace for e-signature software, Free Tier, Business Support.

RemitKo — OFW remittance with KYC & fraud detection

Kubernetes microservices + saga workflow + exactly-once messaging + multi-Region ledger

Real-world problem

Filipino workers abroad send money home. A transfer can never be posted twice or lost, the app must be fast from Dubai or Hong Kong, every new user needs identity checks, fraud must be caught in milliseconds, and auditors require PCI DSS evidence.

Walk the request: all 14 steps in one list
  1. An OFW in Dubai opens the app. Global Accelerator gives fixed IP addresses and carries traffic over the AWS global network to the nearest healthy endpoint.
  2. WAF blocks bots and credential stuffing; Shield Advanced adds a DDoS response team and cost protection.
  3. API Gateway validates tokens and rate-limits each user.
  4. Transfer microservices run on EKS, because the company already standardized on Kubernetes.
  5. New users pass KYC: Rekognition compares a selfie with the ID photo.
  6. Every transfer gets a fraud score from a SageMaker endpoint trained on past transactions.
  7. Approved transfers start a Step Functions workflow (debit → FX → payout) with retries and compensating steps if one fails.
  8. A DynamoDB idempotency key guarantees a retried request never sends money twice.
  9. Payout instructions go into SQS FIFO: strict order, exactly-once processing.
  10. Payouts reach partner banks and e-wallets over PrivateLink, never the public internet.
  11. The family in the Philippines receives the money.
  12. Every movement is posted to the ledger in Aurora Global Database.
  13. Aurora replicates to a second Region, typically in under a second, for disaster recovery.
  14. Encryption keys live in KMS with a custom key store backed by CloudHSM, a single-tenant HSM the company controls.

4-domain map

D1Cloud Concepts · 24%

Fault tolerance (saga, retries, idempotency, 2 Regions) vs. plain high availability. 7 Rs: Refactor the old monolith into microservices. Go global in minutes over the AWS backbone. Well-Architected: Reliability and Security.

D2Security & Compliance · 30%

WAF, Shield Advanced, Firewall Manager, KMS + CloudHSM, Security Hub, Detective, Audit Manager (your PCI evidence), Artifact (AWS's PCI DSS report), Organizations SCPs, Directory Service, Client VPN, least-privilege IAM. Shared responsibility: AWS runs the EKS control plane; the company secures worker nodes, containers and data.

D3Technology & Services · 34%

Global Accelerator, API Gateway, EKS, ECR, Step Functions, DynamoDB, SQS FIFO, PrivateLink, Aurora Global Database, CloudWatch, X-Ray, Elastic Disaster Recovery. AI/ML: SageMaker, Rekognition.

D4Billing, Pricing & Support · 12%

Compute Savings Plans for steady EKS nodes, Enterprise Support with a designated TAM, Cost Anomaly Detection, Cost and Usage Report, Shield Advanced cost protection against DDoS-driven scaling charges, consolidated billing.

Batch 7: multi-answer & NOT trainer

90 questions built for the formats that cost points: Select TWO, Select THREE, and NOT / odd-one-out, including 30 on topics found in your outside practice sources. Instant feedback on every option.

Select TWO / THREE

  1. Circle the number first. Picking fewer = wrong, with no partial credit.
  2. Judge each option as its own true/false statement.
  3. Cross out the sure-wrong ones; what's left is usually your answer.

NOT / EXCEPT / incorrect

  1. Underline the NOT. It's the most-missed word on the exam.
  2. Flip the question: three options are TRUE; find the FALSE one.
  3. Before you click, read your pick back with the question: "X is NOT…" Does it make sense?

Odd one out

  1. Name the group first ("serverless", "7 Rs", "identity services").
  2. Test each option against that group.
  3. Watch for look-alikes: Reserve vs. Rehost, Scalability vs. a pillar.
